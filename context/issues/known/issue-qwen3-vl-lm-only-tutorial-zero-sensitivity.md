# Status: Open

Issue: Qwen3-VL LM-only tutorial reports show zero sensitivity (NONE-only AutoQuant solutions)
============================================================================================

Context
-------

This repo has two ways to run “LM-only” per-layer sensitivity for Qwen3-VL:

1. **Tutorial packs** (self-contained smoke tests)
   - Example (8B): `docs/tutorial/howto/tut-qwen3-vl-8b-introduce-model-layer-sensitivity/`
   - These are intentionally tiny (1 sample, short seq len) and snapshot a sanitized
     `expected_report/`.

2. **Historical published Hydra artifacts** committed under model directories
   - Example (4B, older run): `models/qwen3_vl_4b_instruct/layer-analysis/lm-only/2025-12-17_05-10-42/wint8_aint8/`
   - These were generated by the Hydra runner and contain non-zero per-layer sensitivity values.

The problem is that current tutorial-pack LM-only outputs show **all sensitivities as 0**,
which is confusing because the older Hydra run produced meaningful non-zero values.


Symptoms / Problem
------------------

- In the tutorial pack LM-only expected outputs:
  - `docs/tutorial/howto/tut-qwen3-vl-8b-introduce-model-layer-sensitivity/expected_report/lm_only_int8/layer-sensitivity-report.md`
  - Sensitivity values are `0.000e+00` for all layers.
  - The corresponding manifest shows AutoQuant selected **only** `NONE(effective-bits: 16.0)` recipes,
    with `autoquant_state.score = 0` and `effective_bits = 16.0`.

- In the historical Hydra run:
  - `models/qwen3_vl_4b_instruct/layer-analysis/lm-only/2025-12-17_05-10-42/wint8_aint8/per-layer-sensitivity.md`
  - Sensitivity values are non-zero, and many layers include both `INT8_DEFAULT_CFG(...)` and `NONE(...)`
    candidates in `layer_sensitivity`.

Why this happens (current hypothesis)
-------------------------------------

The tutorial-pack LM-only run is not producing a meaningful “INT8 vs NONE” comparison. Instead,
AutoQuant ends up with **only NONE candidates** and thus all scores/importance collapse to 0.

Most likely contributors:

1. **Scoring/calibration budget is extremely small in the tutorial packs**
   - `max_calib_samples=1`, `calib_seq_len=64`, `batch_size=1`, `score_size=1`.
   - This is useful for “does it run?” but may be too small for AutoQuant to find a feasible
     INT8 recipe under constraints for this model family.

2. **ModelOpt preset / version behavior drift**
   - The historical artifacts were produced on 2025-12-17 and show `INT8_DEFAULT_CFG(...)` candidates.
   - Current default env runs (tutorial pack snapshots) yield `NONE(...)` only.
   - A plausible cause is that the ModelOpt INT8 presets / enablement semantics changed across versions
     (e.g., `INT8_DEFAULT_CFG` includes `quant_cfg.default.enable = False` in the current build).

3. **LM-only implementation differences**
   - The Hydra runner passes an “effective quant cfg” explicitly (`quantization_formats=[effective_cfg]`)
     and records extra metadata.
   - The tutorial uses a CLI driver path with a different scheme/config naming and a tiny dataset.


Impact
------

- Readers compare:
  - tutorial-pack `lm_only_int8` report (all zeros) vs
  - published `lm-only/2025-12-17...` reports (non-zero),
  and assume the tutorial is broken or misconfigured.

- Tooling confidence suffers because “LM-only sensitivity” looks inconsistent across docs/artifacts.


Reproduction
------------

1. Run the tutorial pack (8B example):

```bash

```

2. Inspect:

- `docs/tutorial/howto/tut-qwen3-vl-8b-introduce-model-layer-sensitivity/expected_report/lm_only_int8/quant_manifest.json`
- `docs/tutorial/howto/tut-qwen3-vl-8b-introduce-model-layer-sensitivity/expected_report/lm_only_int8/layer-sensitivity-report.md`

3. Compare against the historical published run:

- `models/qwen3_vl_4b_instruct/layer-analysis/lm-only/2025-12-17_05-10-42/wint8_aint8/per-layer-sensitivity.md`
- `models/qwen3_vl_4b_instruct/layer-analysis/lm-only/2025-12-17_05-10-42/wint8_aint8/wint8_aint8_autoquant_lm_quant_manifest.json`


Workarounds
-----------

- Prefer the Hydra LM-only runner with a non-trivial dataset size when you need meaningful LM-only
  sensitivity values:

```bash
pixi run python scripts/qwen/qwen3_lm_sensitivity.py \
  output_layout=tmp \
  quant_pair=wint8_aint8_lm_only \
  dataset.size=medium
```


Next steps / Fix ideas
----------------------

1. Decide what the tutorial pack’s LM-only pass should validate:
   - If it is only a “pipeline smoke test”, keep it tiny but document clearly that values may be 0.
   - If it is intended to validate *meaningful* sensitivity output, increase scoring/calibration
     to a small-but-nontrivial level (e.g., 16 samples, score_size 16–32, seq_len 256–512).

2. Investigate ModelOpt preset behavior differences:
   - Pin/record ModelOpt versions for the historical run vs current Pixi env.
   - If needed, introduce an explicit “LM INT8 enabled” config (e.g., a custom quant cfg that enables
     quantization defaults while keeping the known safe disable patterns like `*lm_head*`).

3. Align artifacts naming/format:
   - Historical Hydra outputs use `per-layer-sensitivity.{md,json}`.
   - New CLI drivers emit `layer-sensitivity-report.{md,json}` and a different manifest shape.
   - Consider emitting both names or adding compatibility notes.
