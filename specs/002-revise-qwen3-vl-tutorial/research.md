# Research: Revise Qwen3-VL-8B Tutorial Pack (Introduce + Layer Sensitivity)

**Branch**: `002-revise-qwen3-vl-tutorial`  
**Date**: 2026-01-21  
**Spec**: `/data1/huangzhe/code/auto-quantize-model/specs/002-revise-qwen3-vl-tutorial/spec.md`

## Context

This feature revises the tutorial pack at:

- `/data1/huangzhe/code/auto-quantize-model/docs/tutorial/howto/tut-qwen3-vl-8b-introduce-model-layer-sensitivity/`

Key constraints:

- Everything runs via Pixi (`pixi run ...`) in the default environment.
- Default run executes and verifies **4 scenarios**:
  - all-layers × `wint4_afp16`
  - all-layers × `wint4_aint8`
  - LM-only × `wint4_afp16`
  - LM-only × `wint4_aint8`
- Default dataset preset is **medium** (128 samples, seq_len=512, batch_size=8, num_calib_batches=16, score_size=128).
- Missing assets (model or datasets) must fail fast with actionable guidance.
- Verification diffs **only** sanitized summaries.

## Decisions

### D1: LM-only runner entrypoint

- **Decision**: Use the existing Hydra runner at `/data1/huangzhe/code/auto-quantize-model/scripts/qwen/qwen3_lm_sensitivity.py` for LM-only tutorial scenarios.
- **Rationale**: It already supports `quant_pair` selection (including INT4 examples), records dataset metadata (samples + batches), and aligns with the repo’s modern configuration patterns.
- **Alternatives considered**:
  - Continue using the legacy tutorial-pack LM-only helper under `/data1/huangzhe/code/auto-quantize-model/models/qwen3_vl_4b_instruct/helpers/...`: rejected because it is not designed for the new quant-pair examples and has historically produced degenerate “all zero” sensitivities under tiny calibration budgets.

### D2: All-layers runner strategy for INT4 quant pairs

- **Decision**: Extend the existing all-layers driver at `/data1/huangzhe/code/auto-quantize-model/models/qwen3_vl_4b_instruct/helpers/qwen3_vl_4b_autoquant_all_layers/run_qwen3_vl_4b_autoquant_all_layers.py` to support selecting INT4 quantization formats (via quant-pair config) and to emit complete dataset metadata.
- **Rationale**: Keeps the tutorial pack self-contained and minimizes new surface area while enabling the required worked examples.
- **Alternatives considered**:
  - Create a new Hydra “VLM all-layers sensitivity” runner: deferred because it increases scope (new config groups + runner wiring) without being strictly required for the tutorial pack goals.

### D3: Dataset assets and presets

- **Decision**: Reuse repo dataset assets:
  - COCO root symlink at `/data1/huangzhe/code/auto-quantize-model/datasets/coco2017/source-data`
  - VLM calib DB at `/data1/huangzhe/code/auto-quantize-model/datasets/vlm-quantize-calib/coco2017_vlm_calib_{small,medium,large}.db`
  - Captions at `/data1/huangzhe/code/auto-quantize-model/datasets/vlm-quantize-calib/coco2017_captions_{small,medium,large}.txt`
- **Rationale**: These are already curated and versioned in-repo; the tutorial can stay lightweight while referencing external COCO images via a local symlink.
- **Alternatives considered**:
  - Generate synthetic 1-sample datasets in the tutorial pack: rejected because it produced confusing/degenerate LM-only results and does not meet the “medium by default” requirement.

### D4: Verification surface

- **Decision**: Keep verification diffs limited to sanitized summaries (`summary.json` + `summary.md`) per scenario.
- **Rationale**: Most stable across machines and dependency versions; avoids brittle diffs on raw binary/state artifacts.
- **Alternatives considered**:
  - Diff full `expected_report/`: rejected due to high churn and poor portability.

### D5: Non-degeneracy check for sensitivity

- **Decision**: Treat only exact `0.0` as zero for the “all-zero sensitivities” regression check.
- **Rationale**: Matches clarified spec; minimizes false positives from extremely small non-zero values.
- **Alternatives considered**:
  - Epsilon-based checks (`abs(x) < 1e-6`): rejected per clarified spec.

### D6: Default scenario coverage

- **Decision**: Default `run_demo.sh` executes all four scenarios; provide an optional way to run a subset for iteration.
- **Rationale**: Prevents “it passed but didn’t test LM-only / a quant-pair” ambiguity while still enabling faster dev loops when needed.
- **Alternatives considered**:
  - Run only one scenario by default: rejected because it weakens the tutorial pack as a regression guardrail.
